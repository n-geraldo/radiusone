# RadiusOne 2.3.4

Fixes the updater, with 2.3.3's fixes. Update with *Settings → Overview → Software update*, or `sudo radiusone-update`.

- **The portal reads its settings after an update.** Copying a release made the whole app folder its owner's,
  `.env` included, so the web user lost access to `.env` (installed as root:www-data, 0640). `.env` now keeps its
  owner and mode.
- **An update no longer stops on a package the new release leaves out** (from 2.3.3): artisan's package lists are made
  again after the new files are copied.
- **The portal works after a rollback** (from 2.3.3): the session, cache and compiled-view folders are created again.
- **RadiusOne's new mark**, the Key, from the PingOmni family.

## Installing

- **Servers on 2.3.0 to 2.3.3:** *Settings → Overview → Software update* → **Install RadiusOne 2.3.4**, or
  `sudo radiusone-update`. A server whose update stopped (the faults above) still runs its old updater: put 2.3.4's
  in place first, then update:

      curl -fsSL https://raw.githubusercontent.com/n-geraldo/radiusone/v2.3.4/ops/radiusone-update | sudo install -m 0755 /dev/stdin /usr/local/sbin/radiusone-update
      sudo radiusone-update

- **Servers on 2.2:** install 2.3.4 with the update button, then **Finish moving to RadiusOne**.
- **New servers:** see INSTALL.md.
